------------------------------------------------------------------------

# 一、项目最终定位

XiaoG 不是单纯聊天网页。

XiaoG 是一个个人 AI Runtime 核心系统。

目标：

构建一个属于用户自己的、可扩展、可控制、安全的个人智能环境。

未来可以扩展为：

-   Web应用
-   Windows应用
-   macOS应用
-   iOS应用
-   Android应用

但当前优先级：

核心Runtime能力 \> 载体形态。

# 四、核心能力地图

目标：

支持任意兼容AI模型服务。

能力：

-   添加Provider
-   添加API
-   添加模型
-   Provider状态检测
-   Provider配置管理

不为具体模型写死UI。

# 六、开源复用策略

原则：

Open Source First，但不是依赖堆叠。

流程：

    需求出现

    ↓

    判断是否属于XiaoG核心价值

    ↓

    寻找成熟开源

    ↓

    License检查

    ↓

    POC

    ↓

    Adapter

    ↓

    决定集成

要求：

-   MIT
-   Apache-2.0
-   BSD优先

避免：

-   架构控制权丢失
-   新固定成本
-   高维护负担

------------------------------------------------------------------------

# 七、Harness定位

Harness不是XiaoG核心。

定位：

未来Agent Runtime增强组件。

路线：

    POC

    ↓

    Deep POC

    ↓

    Adapter Pilot

    ↓

    决定是否采用

架构：

    XiaoG Core

    ↓

    Harness Adapter

    ↓

    Execution Layer

禁止：

Harness控制XiaoG核心。

# 十、明确边界

不做：

-   为单模型定制系统
-   为炫技提前引入复杂架构
-   为了部署而部署
-   为了开源而堆开源组件

所有技术选择必须服务于：

稳定、可维护、长期使用的个人AI Runtime。

------------------------------------------------------------------------

# 十一、最终愿景

XiaoG最终目标：

成为一个个人拥有、个人控制、可持续扩展的AI Runtime平台。

它不是某一个模型的入口。

它是：

用户自己的AI基础环境。
