# 四、重大决策记录

------------------------------------------------------------------------

# 决策1：双Codex并行 → Single Codex

## 原方案

两个Codex同时工作：

-   一个开发
-   一个审查

------------------------------------------------------------------------

## 调整原因

实际开发过程中发现：

-   上下文连续性更重要；
-   多环境同步成本增加；
-   状态容易分裂。

------------------------------------------------------------------------

## 当前决定

采用：

Single Codex Governance。

一个Codex负责：

-   开发
-   测试
-   提交
-   报告

ChatGPT负责：

-   架构
-   规划
-   Review

------------------------------------------------------------------------

# 决策2：GitHub接入时机调整

## 原方案

较早接入GitHub辅助开发。

------------------------------------------------------------------------

## 调整原因

当前阶段：

-   本地开发领先；
-   路线正在调整；
-   需要先确定第三版规划。

------------------------------------------------------------------------

## 当前决定

Roadmap v3定稿后同步GitHub。

采用：

Minimal GitHub Governance。

保留：

-   main
-   commit
-   tag
-   changelog

不引入复杂流程。

------------------------------------------------------------------------

# 决策3：DeepSeek Harness策略调整

## 原方案

尝试使用Harness作为小G底座组成部分。

------------------------------------------------------------------------

## 调整原因

POC发现：

Harness具有价值，但仍存在：

-   alpha阶段风险
-   生命周期风险
-   架构控制风险

------------------------------------------------------------------------

## 当前决定

不直接集成。

路线：

POC

↓

Deep POC

↓

Adapter Pilot

↓

决定是否采用

------------------------------------------------------------------------

原则：

Harness增强XiaoG，而不是控制XiaoG。

------------------------------------------------------------------------

# 决策4：开源复用策略

确定：

Open Source First，但不是简单堆叠。

------------------------------------------------------------------------

采用流程：

需求出现

↓

判断是否属于XiaoG核心价值

↓

寻找成熟开源

↓

License检查

↓

POC

↓

Adapter

↓

决定集成

------------------------------------------------------------------------

要求：

-   MIT
-   Apache-2.0
-   BSD优先

避免：

-   架构失控
-   新固定成本
-   高维护风险

------------------------------------------------------------------------

# 决策5：Provider架构方向

确定：

Provider Ecosystem方向。

核心原则：

Capability Driven UI。

------------------------------------------------------------------------

不采用：

提前写死模型UI。

例如：

禁止：

-   DeepSeek按钮
-   Claude按钮
-   Gemini按钮

------------------------------------------------------------------------

采用：

Provider能力描述

↓

动态生成：

-   模型入口
-   设置项
-   推理档位
-   路由能力

------------------------------------------------------------------------

# 决策6：Local First

确定：

用户数据优先属于用户。

原因：

XiaoG定位为个人AI Runtime。

------------------------------------------------------------------------

影响：

采用：

-   本地数据
-   本地配置
-   用户控制

未来扩展云端时，需要重新设计数据边界。
